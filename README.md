# SoukMind AI

**An evolving AI engineering project for retail demand prediction, analytics, and decision support.**

**Status:** v0.1 — educational prototype · **Language:** Python · **Current model:** Multiple Linear Regression

## Overview

SoukMind AI aims to become an end-to-end retail intelligence platform. The first milestone trains a regression model to estimate daily units sold using product price, advertising budget, promotional discounts, and a weekend indicator.

**Important:** This release uses **synthetic data**. Reported metrics describe a controlled learning experiment, not measured performance in real Moroccan businesses. Future modules (computer vision, NLP, LLMs, MLOps, and big-data pipelines) are planned, **not implemented**.

## Current workflow

1. Generate a reproducible synthetic sales dataset (`numpy` random generator, seed `42`).
2. Create four features: `price`, `ad_budget`, `discount_pct`, `weekend`.
3. Split chronologically: first 80% of rows for training; final 20% for testing.
4. Fit a `scikit-learn` `LinearRegression` model.
5. Compare it with a mean-of-training-sales baseline.
6. Measure MAE and RMSE; inspect actual vs predicted sales and residuals.

### Model

The linear predictor is

`units_sold_hat = intercept + w1*price + w2*ad_budget + w3*discount_pct + w4*weekend`

For the first experiment, fitted coefficients were approximately:

| Parameter | Value |
| --- | ---: |
| Intercept | 101.8719 |
| `price` | -1.0465 |
| `ad_budget` | 0.1541 |
| `discount_pct` | 49.6048 |
| `weekend` | 7.7767 |

`discount_pct` is encoded as a fraction (`0.10` means 10%); a 0.10 increase corresponds to roughly 4.96 additional *predicted* units, holding the other features fixed. **These coefficients are not causal estimates.**

## Results: experiment 001

Metrics below are from the held-out synthetic test set:

| Model | Test MAE | Test RMSE |
| --- | ---: | ---: |
| Training-mean baseline | 13.171 | 16.436 |
| Multiple Linear Regression | **4.929** | **5.807** |

The linear model reduced test MAE by approximately **62.6%** relative to the baseline. A local reproduction using the previously supplied seed-42 generator yielded **Train MAE = 3.805** and **Train RMSE = 4.886** (test-minus-train gaps: **+1.124 MAE** and **+0.921 RMSE**). These reproduction values should be confirmed against the local project by running `src/evaluate.py`. A small gap on synthetic data does not establish real-world generalization. See [experiment notes](docs/experiment_001.md).

## Quick start (Ubuntu / Linux)

Requires Python 3.10+.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install numpy pandas scikit-learn matplotlib joblib

# First generate the dataset and predictions:
python src/train.py

# Recompute metrics on the saved dataset:
python src/evaluate.py

# Analyze the residuals (requires data/predictions.csv):
python src/analyze.py
```

`src/evaluate.py` writes `reports/experiment_001_metrics.json`. Its output is a reproducible reference for the train/test gap. Run `train.py` first if `data/sales.csv` is missing.

## Validation notes

- The chronological holdout is appropriate for a basic time-ordered evaluation, but it does not by itself validate a real forecasting system.
- When predicting *future* sales, all features must be known at prediction time. Plans for promotions and ad budgets must be set in advance to avoid leakage.
- Residual plots can reveal patterns but cannot prove the absence of overfitting.
- The dataset was generated with a near-linear process, which favors linear regression. Real sales data may be far more complex.
